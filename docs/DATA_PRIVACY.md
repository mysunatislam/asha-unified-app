# Data and privacy boundaries

- Camera frames, photo pixels and microphone recordings are not retained by Everyday. Vision and image quality run locally. Food photos exist only in the mounted view and object URLs are revoked on removal/navigation.
- Browser-native speech input is opt-in and explicitly discloses that the browser may send audio to its own recognition service. It is not an offline-ASR claim. A bounded 90-second session survives silence, pauses during Asha's speech and stops on navigation/backgrounding.
- Records default to session memory. Reloading clears them unless the user creates an encrypted vault. AES-GCM-256 encrypts records and preferences; PBKDF2-SHA256 with a random 16-byte salt and 210,000 iterations derives a non-exportable key from a 10–1024-character passphrase. Each ciphertext uses a random 12-byte IV. Passphrases and keys are never stored.
- Lock cancels outstanding writes and removes in-memory plaintext. Atomic IndexedDB transactions and vault/policy identity guards prevent stale tab writes from reviving deleted/revoked data. The vault is not protection against malicious code executing in an unlocked same-origin page, browser compromise or a compromised device. No key recovery exists.
- Local retention is 7, 30 or 90 days in the UI, enforced on access/save/unlock. Module-saving revocation removes that module's local records. Exports are intentionally unencrypted and also displayed as copyable text if OS downloads are blocked. Delete removes Everyday records and vault metadata, not the legacy assistive app's independently managed records.
- Optional timing telemetry is local, off by default and bounded to 500 samples. No analytics upload was added. Language/theme alone use localStorage; cloud session and clinic credentials use tab sessionStorage. Model cache pointers contain no health records.
- Care sends only a consented question and optionally five selected recent Care facts. Context is bounded, retains provenance and is explicitly treated as unverified quoted data. MAIRA credentials remain server-side. Existing provider retention terms require operator review before a clinical launch.
- Clinic scopes do not upload history by themselves. The patient must separately select records and confirm sharing. Shared copies retain source/time/model/correction metadata. Revocation hides them immediately, deletes server copies and invalidates the grant ID; renewed permission does not resurrect previous copies. Copies already viewed/exported by another person cannot be remotely erased.
- Clinic role links are credentials: keep them private. The server stores only token hashes. Demo workspaces and roles expire after 30 days. The existing authenticated cleanup cron also removes expired Everyday tenants and shared records older than 30 days. Keys remain in the existing private store; no public client database policy was introduced.
- Production storage encryption, backups, region, retention, staff access, incident handling and applicable health-data regulation need a deployment-specific assessment. A clinician role is self-attested and is not verified professional identity. No continuously staffed monitoring service is claimed.

The browser suite verifies ciphertext in IndexedDB, incorrect passphrase rejection, lock/unlock, export payload, deletion and explicit clinic record sharing. Security tests cover consent-write races, deletion failures, tenant/role/patient isolation and expiry. Physical-device, accessibility and external security review remain pending.
